# Ship a wallpaper app that disappears

Build backreel as a single native Rust executable that Windows Task Scheduler launches once a day and that exits as soon as the wallpaper is set, so nothing stays resident between runs. That one decision does more for footprint than any language choice: idle RAM and CPU attributable to the app are zero, while Microsoft's Bing Wallpaper sat at **192.3 MB working set and 109.2 MB private** on the test machine. A measured prototype of the core path came to **224,768 bytes with no runtime dependency**, using Windows' own WinHTTP, WIC and `IDesktopWallpaper` instead of bundled libraries. The harder problem is image sourcing, not code: **Unsplash and Pexels name wallpaper apps as barred uses**, so the default install should rest on keyless open-licence sources (Wikimedia Commons, NASA, the Met, the Art Institute of Chicago), with Bing as an opt-in after legal review. Categories need a fixed backreel list that per-source adapters translate into each provider's query, and a small remote manifest should hold those mappings so a broken endpoint never needs an app release. Distribute a signed portable exe through GitHub and WinGet first, because the Store's MSIX packaging is free and warning-free but has no documented path for the scheduled task the design depends on. No complete product has been built: wallpaper setting, scheduling and signing are all untested end to end, and the prototype's memory figure understates a real run.

## Residency, not language, decides the footprint

A wallpaper job is needed once a day, yet the official app keeps a process alive around the clock. Its current package is a **46.0 MB download that unpacks to 85.7 MB, of which 63.5 MB is DLLs**, plus a Windows App Runtime dependency, and it carries browser-default machinery alongside the wallpaper logic ([package](https://download.microsoft.com/download/3c0e11a1-2e57-4bc3-b877-1a04248078a4/W011/0x00005001/BingWallpaper_1.1.459.0_x86.msix)). The 109.2 MB private figure is one observation on one machine ([local check](../research_notes/Minimal%20Windows%20wallpaper%20app%20design/windows_mechanics.md)), but it lines up with a user review objecting to over 100 MB of RAM ([AlternativeTo](https://alternativeto.net/software/bing-wallpaper/about)).

Four process models were compared. A tray app always holds memory, and a hand-written Win32 one is estimated (not measured) at a few MB. A service needs admin rights and cannot touch the user's desktop directly, because services run in session 0 ([Interactive Services](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services)). A Run key fires only at logon with no timing guarantee ([Run and RunOnce](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)). A per-user Scheduled Task with a short-lived exe costs nothing between runs, because the Schedule service already runs anyway, and a non-admin can register one under their own account with no password ([Security Contexts](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)). Use the interactive logon type, not S4U, because S4U tasks need a batch-logon privilege that standard users lack by default.

The task defaults are traps. The schema defaults to refusing to start on battery and stopping when the machine goes onto battery, which would silently kill daily refresh on laptops ([settingsType](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-settingstype-complextype)). Microsoft's own Bing Wallpaper task offers a working template: `InteractiveToken`, both battery flags false, a 5-minute limit, `StartWhenAvailable` true, and the user SID in the task name ([local check](../research_notes/Minimal%20Windows%20wallpaper%20app%20design/windows_mechanics.md)).

| Task setting | Value | Reason |
|---|---|---|
| Triggers | Daily calendar + logon (1-minute delay) | `StartWhenAvailable` queues missed runs with a [10-minute delay](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-startwhenavailable); logon catches the rest |
| `DisallowStartIfOnBatteries`, `StopIfGoingOnBatteries` | false | Schema default is true |
| `StartWhenAvailable` | true | Catches a laptop asleep at trigger time |
| `WakeToRun` | false | Waking a machine to change an unseen wallpaper wastes battery |
| `RunOnlyIfNetworkAvailable` | false | Check network in the app instead |
| `ExecutionTimeLimit` | PT5M | The [default is 72 hours](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings) |
| `Priority` | 7 (default) | [Below-normal CPU, low I/O and memory priority](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-priority-settingstype-element) |

Every run must be idempotent: the exe reads its state and exits within milliseconds if today's wallpaper is already set, which is what makes multiple triggers safe. It must never sleep waiting for a network, since that recreates a resident process. On failure it rotates a cached image, marks the day pending and exits, and the next trigger retries. One binary serves every role: no flag opens settings, `--run` is the headless job, `--next` skips the daily gate, and `--install` and `--uninstall` manage the task. A named mutex guards against a manual run colliding with a scheduled one, since `IgnoreNew` covers only task instances.

Dropping the tray has real costs. There is no one-click "next", no live reaction to a monitor being plugged in, and a failure stays invisible until settings is opened. Silent refresh failure is already a recurring Bing complaint ([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/5834019/troubleshooting-bing-wallpaper-that-doesnt-automat)). The answer is a Start menu shortcut for settings, a second one for `--next`, a status line showing last and next run, and a monitor-signature check at each trigger that re-renders from cached originals with no network. That is worse than a tray for frequent fiddlers and better for the stated goal, which is why it is the right trade here.

### A Rust binary of about 225 KB is the practical floor

Equivalent test apps were built per stack and run on an i9-13980HX. The `daily` test fetched the Bing JSON, downloaded a 327 KB JPEG and read its dimensions. All figures below are measured ([benchmark notes](../research_notes/Minimal%20Windows%20wallpaper%20app%20design/stack_and_distribution.md)), with warm starts only, and with Tauri and Electron as single samples.

| Stack | File size | Daily run peak private | Settings window private | Runtime needed |
|---|---|---|---|---|
| C, MSVC, no CRT | 8 KB | 3.7 MB | 2.0 MB | None |
| **Rust `std`, `+crt-static`, serde_json** | **225 KB** | **3.8 MB** | **2.1 MB** | **None** |
| Go 1.25 | 6.1 MB | 18.9 MB | 14.6 MB | None |
| C#, .NET Framework 4.8 | 6.6 KB | 21.1 MB | 22.4 MB | In Windows |
| C#, .NET 10 | 162 KB + 8 KB | 12.0 MB | 10.4 MB | 170 MB shared runtimes on disk |
| Tauri 2 (WebView2) | 2.5 MB | Not run | 155 MB, 7 processes | WebView2 |
| Electron 38 | 324 MB unpacked | Not run | 145 MB, 4 processes | Bundled |

Native stacks tie at runtime because the 14-17 MB working set is mostly Windows DLLs, not language. `no_std` Rust matches C at 8 KB but buys only about 190 KB of file size and nothing measurable while running, at the price of hand-written runtime stubs. C only wins if the file size is itself the goal. Rust `std` with a static CRT keeps memory safety and removes the VCRUNTIME dependency for 99 KB. Keep serde_json: it adds 23.5 KB, and a hand-rolled parser produced a silent empty-URL bug during this very test. Swapping WinHTTP for reqwest and rustls raises the binary to **1.76 MB and 132 lockfile packages** and takes on a TLS stack you must patch yourself.

Two caveats matter. Tauri's 4.8 MiB installers look minimal, but its measured memory roughly equals Electron's, which agrees with a report on [Tauri issue #5889](https://github.com/tauri-apps/tauri/issues/5889). And **the 3.8 MB peak is a floor, not a forecast.** The prototype never decoded a full image or called `SetWallpaper`. A real run must decode, scale and re-encode, and an uncompressed 3840x2160 BGRA frame alone is about 33 MB if held whole. The same applies to the 0.3-second run time, which reflects a 327 KB download, whereas a Bing UHD image is 3.7 MB. Plan on tens of MB for a few seconds a day until a real run is measured. Do not publish the prototype figures as product figures.

`windows-sys` has no COM wrappers in this setup, so WIC and `IDesktopWallpaper` were called through hand-written vtable indices. That is the one fragile spot in the stack, and it deserves tests. Skip Native AOT, which [lacks built-in COM](https://learn.microsoft.com/pt-pt/dotnet/core/deploying/native-aot), and skip WinUI 3, which reached 48.9 MB only after aggressive trimming ([developer notes](https://raw.githubusercontent.com/Phoenix-/ForceAutoHDR.Net/main/notes/winui3-aot-payload-trim.md)).

For settings, use a native dialog in the same exe, with common controls v6 via manifest and a Per-Monitor V2 manifest. The official limit of the Windows 11 look is a [dark title bar](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-windows-themes) and [Mica](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type). Dark controls need [undocumented uxtheme ordinals](https://gist.github.com/rounk-ctrl/b04e5622e30e0d62956870d5c22b7017) that could break in any build, so accept a plain dialog or custom-draw selectively. An on-demand WebView2 window would also cost nothing at idle, but it costs about 150 MB while open to render one combo box and a few checkboxes.

## Windows already ships every component the daily run needs

**`IDesktopWallpaper` is the only documented per-monitor API** and should be primary ([docs](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-idesktopwallpaper)), with `SystemParametersInfoW` as an all-monitor fallback. The WinRT setter has no monitor parameter. Position mode appears to be global, so render each image to its monitor's exact pixels and use FILL, at which point the mode stops mattering. Three details bite. `GetMonitorRECT` returns S_FALSE for a detached monitor, which passes `SUCCEEDED()`, so test for S_OK ([docs](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-idesktopwallpaper-getmonitorrect)). The apartment model is contested, so initialise STA, which satisfies the stricter claim at no cost. Success codes are weak evidence, so read back with `GetWallpaper` after setting. Use a unique filename per image: the rule is [documented only for WinRT](https://learn.microsoft.com/en-us/uwp/api/windows.system.userprofile.userprofilepersonalizationsettings), but it costs nothing.

Avoid everything undocumented. Microsoft held back 24H2 from PCs running wallpaper customisation apps for about six months and never published the trigger ([The Register](https://www.theregister.com/2025/04/14/windows_11_24h2_hold/)). That argues against the Progman `0x52C` message, WorkerW manipulation and the build-pinned `IVirtualDesktopManagerInternal`, even though the last is the only route to per-desktop wallpaper ([winvd](https://docs.rs/crate/winvd/latest/source/src/interfaces.rs)).

For images, WIC replaces any bundled codec. The chain is decoder, then scaler, then clipper, then format converter, then JPEG encoder at roughly 0.92-0.95 quality with 4:4:4 subsampling. The scaler must sit directly after the frame decode so JPEG can [scale natively during decoding](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/nn-wincodec-iwicbitmapsourcetransform), and [`HighQualityCubic`](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/ne-wincodec-wicbitmapinterpolationmode) suits large downscales. The benchmark notes suggest WIC might be skippable by handing the file straight to the wallpaper API. That holds for a single-source Bing clone, not here: multiple sources mean arbitrary aspect ratios, and the decode step is also the junk filter. Treat JPEG and PNG as the only guaranteed formats, since [WebP, HEIF and AVIF depend on extensions](https://learn.microsoft.com/en-us/windows/win32/wic/native-wic-codecs). Downloaded files are untrusted decoder input, so cap response size and reject absurd dimensions with `GetSize` before decoding. If a JPEG already matches the monitor exactly, pass it through, because Windows appears to re-encode into its own `TranscodedWallpaper` cache anyway. That behaviour rests on community reports plus one local observation, not on Microsoft documentation.

Crop math sets source selection. A 16:9 image on a 21:9 monitor keeps about 76% of its height, on 32:9 it keeps 50%, and on a portrait 9:16 panel it keeps about 32% of its width. Compute crop loss per monitor, accept below roughly 25-30%, and otherwise try another candidate or a native-aspect variant. These thresholds are design judgement to tune. Paintings deserve a colour-matched border instead of a crop, since cropping can ruin them.

For network, use WinHTTP in synchronous mode with `WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`, which [handles system and per-user proxy settings](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpopen). This knowingly departs from Microsoft's [general advice to prefer WinINet](https://learn.microsoft.com/en-us/windows/win32/wininet/wininet-vs-winhttp), since backreel needs none of WinINet's cookies, credential prompts or IE zones. The gain is modest, and WinINet would also work. Skip `WINHTTP_FLAG_SECURE_DEFAULTS`, because it forces async; set TLS 1.2 and 1.3 manually instead. Check [`INetworkCostManager`](https://learn.microsoft.com/en-us/windows/win32/api/netlistmgr/nn-netlistmgr-inetworkcostmanager) first. Skip downloads on fixed or variable plans by default, and always skip roaming or near-limit connections unless the user pressed Next. Store ETags per source, retry two or three times within about a minute, honour `Retry-After`, then exit.

The remaining settings are one-liners. Add [EcoQoS](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation) on `--run` but not on `--next` or settings, because a user is waiting there. Keep everything under `%LOCALAPPDATA%\backreel`. Write state as temp-then-rename, since the task limit can kill a run. Before any network work, check the daily gate, then skip remote sessions, [`NoChangingWallPaper`](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-controlpaneldisplay) and wallpaper policies, and then respect the user's first-run choice about replacing Spotlight or slideshow.

Disk is where the footprint actually accumulates. The exe is a rounding error next to the cache, and the suggested 14 rendered sets under a 200 MB cap is a design guess. Bandwidth is the largest daily cost, so request the nearest size a source offers: Wikimedia's `iiurlwidth=3840`, IIIF widths at the museums. Wikimedia returned 400 for a 2560px thumbnail while 1920px and 3840px worked, so only some widths are accepted ([source notes](../research_notes/Minimal%20Windows%20wallpaper%20app%20design/image_sources.md)). Evict originals first, and never delete a file `GetWallpaper` still reports.

## Wallpaper bans eliminate the three obvious stock sources

The instinctive source list is mostly closed. Unsplash's guidelines bar reproducing its core experience, listing "unofficial clients, wallpaper applications, etc." ([API Guidelines](https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines)), and a key cannot be shared across installs ([docs](https://unsplash.com/documentation)). Pexels forbids "making Pexels content available as a wallpaper app" ([docs](https://www.pexels.com/api/documentation/#guidelines)). Pixabay's licence bars standalone distribution and names wallpaper, and its API caps at 1280px without approval ([terms](https://pixabay.com/service/terms/), [docs](https://pixabay.com/api/docs/)). A user's own key moves the credential but does not obviously cure a rule aimed at what the app is, so do not build on that argument without written agreement. A thin proxy has the same flaw: it hides keys for $0-5 a month ([Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)) but leaves the ban in place.

Bing is the emotional centre of "an app like BingWallpaper", and it is legally awkward. The endpoint is undocumented, works keyless, and serves 3840x2160, but only about 15 days of history are reachable. Microsoft's terms limit Bing content to "noncommercial, personal use" and require authorisation for other downloading or copying ([Services Agreement](https://www.microsoft.com/en-us/servicesagreement)). Sampled credits are Getty. Spotlight shares that legal shape and adds an ad-delivery endpoint found through traffic analysis ([SpotlightAPI.md](https://raw.githubusercontent.com/ORelio/Spotlight-Downloader/master/SpotlightAPI.md)). A free app fetching on the user's device reads closer to that clause than a paid one, but that is a non-lawyer's reading and needs real advice.

| Phase | Source | Default | Why |
|---|---|---|---|
| v1 | [Wikimedia Commons](https://api.wikimedia.org/feed/v1/wikipedia/en/featured/2026/11/03) | On | Daily picture, per-file licence data, originals around 5000px in samples |
| v1 | [NASA Image Library](https://images-api.nasa.gov/search?q=nebula&media_type=image&page_size=2) | On | Keyless, strong for Space; resolution varies |
| v1 | [NASA APOD, new endpoint](https://science.nasa.gov/wp-json/wp/v2/apod-basic) | On, items with no `copyright` value only | [Some images are copyrighted](https://science.nasa.gov/apod/apod-about) |
| v1 | [The Met](https://metmuseum.github.io/) | On | 4000px class; check public-domain status per object |
| v1 | [Art Institute of Chicago](https://api.artic.edu/api/v1/artworks/search?q=landscape&limit=1) | On | Good subject data; images returned 403 without an `AIC-User-Agent` header |
| v1 | [Bing](https://www.bing.com/HPImageArchive.aspx?format=js&idx=0&n=1&mkt=en-US) | Off, opt-in, after legal review | Best daily photos; unofficial, personal use only |
| v1.1 | [Rijksmuseum](https://data.rijksmuseum.nl/docs/search) | On | 5862px sample; thin search, so use curated IDs |
| v1.1 | [National Gallery of Art](https://github.com/NationalGalleryOfArt/opendata) | On | 21,105 large landscape images; 92 MB CSV needs a pre-built index |
| v1.1 | [Wallhaven](https://wallhaven.cc/help/api) | Off, opt-in with rights notice | Only route to Minimal; [user-uploaded, rights unclear](https://wallhaven.cc/about) |
| Later | Smithsonian, Flickr | Off, own key | Add little; [api.data.gov keys must stay private](https://api.data.gov/docs/developer-manual/) |
| Do not ship | Unsplash, Pexels, Pixabay, Reddit, Earth View, NatGeo, Apple | n/a | Terms, approval or format rule them out |

Older guides will mislead you here. **The legacy APOD API goes offline on 1 December 2026** and is already failing, returning HTTP 200 with a NASA logo in place of the image ([catalog](https://api.nasa.gov/assets/json/apis.json), [live test](https://api.nasa.gov/planetary/apod?api_key=DEMO_KEY)). The Met's v1 search was [retired on 1 October 2026](https://collectionapi.metmuseum.org/public/collection/v1/search?q=landscape&hasImages=true), and only v1.1 works. The old Rijksmuseum API returns 410 in favour of a [new one](https://data.rijksmuseum.nl/docs/search), and [`source.unsplash.com`](https://source.unsplash.com/1600x900/?nature) returned 503. These results are one day's snapshot, and the APOD case proves a status code is not validation.

That drives the one piece of infrastructure worth having: a **static manifest** of endpoints and category mappings on any free host, so a dead endpoint is a config change rather than a release. It can also carry the pre-built NGA index and a latest-version field, which makes the update check free. Be careful, though. One of the 2024 allegations against Bing Wallpaper was that it could be [remotely reconfigured](https://www.theregister.com/2024/11/26/bing_wallpaper_app/). Keep the manifest data-only, restrict it to an allow-list of hosts compiled into the binary, publish it openly, and fall back to built-in defaults. Image bytes must go straight from provider CDNs, because a server caching images would make you a redistributor.

Send a compliant User-Agent such as `backreel/1.0 (https://<project-site>)`: Wikimedia allows [200 requests a minute with one and 10 without](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits). Fetching on each device spreads load across user IPs, and a random delay on the trigger spreads it across time. Whether keyless access survives real popularity is unknown, and AIC's intermittent 403s hint at bot defences.

## Categories need a fixed list and a local filter

No two sources share a taxonomy, so backreel should own the list and let adapters translate. Each adapter takes a category plus constraints and returns normalised candidates carrying source, ID, URL, dimensions, licence, creator and credit text. The mapping lives in the manifest. Internally, keep subject, style and medium as separate facets, so a Monet can match both Art and Nature, and a user who wants only photographs can exclude paintings. This shape follows [Variety's one-module-per-source design](https://github.com/varietywalls/variety/tree/master/variety/plugins/builtin/downloaders). Do not copy Variety's retrofit problem, though: its [top multi-monitor issue has been open since 2018](https://github.com/varietywalls/variety/issues/96), so per-monitor state belongs in the data model from day one.

A sensible coverage rule is that a category ships only with two sources or one large pool. Live counts ([Commons](https://commons.wikimedia.org/w/api.php?action=query&format=json&prop=categoryinfo&titles=Category:Featured_pictures_of_landscapes), [Wallhaven](https://wallhaven.cc/api/v1/search?q=nature&categories=100&purity=100), and the other providers listed above) give this picture:

| Category | Keyless open mappings (result counts, 2026-11-04) | Verdict |
|---|---|---|
| Nature | Commons landscapes 492; NASA `earth from space` 19,471; Met `landscape` 5,691; AIC `landscapes` | Strong |
| Space | NASA `galaxy` 1,747, `nebula` 316; Commons astronomy 102 | Strong, NASA-led |
| City | Commons cityscapes 520; AIC `cityscapes` | Good; Met's `Cityscapes` tag returned 0 |
| Architecture | Met 4,504; Commons 49; AIC `architecture` | Good |
| Art | Met European Paintings; AIC public-domain works; Rijksmuseum 4,924 in v1.1 | Strong |
| Animals | Met 4,537; AIC `animals`; Commons needs subcategory recursion (untested) | Adequate |
| Abstract | Met 1,653; AIC `abstract` | Means abstract art, not patterns |
| Minimal | None; Wallhaven `minimalism` 6,929 | Drop from default install |

These counts measure supply, not beauty. Nobody has yet reviewed how many results look good on a desktop. Commons' featured categories pre-filter quality and support `filew:>3839`, which returned 458 landscapes, while Smithsonian's 1.1 million `Animals` hits are likely specimen records. Daily feeds such as Bing and APOD have no categories at all, so treat them as a separate "Daily picks" toggle, with a low-confidence keyword match against title text.

Museums and Wikimedia provide **no safety flags**, and classical art includes nudity and violence on a screen that may be visible at work. Every source therefore passes one local filter: still images only, decode and sanity check, width at least 0.75 times the monitor with a 1920px floor, a download budget near 15 MB (one APOD PNG was [27 MB](https://science.nasa.gov/wp-json/wp/v2/apod-basic)), a recognised open licence for default-on sources, and a deny-list over title, tags and alt text. Make work-safe mode the default and add a one-click "never show again". The Met and NASA report no pixel dimensions before download, so this gate spends bandwidth on those sources. Word lists will miss sparsely tagged images, and an on-device classifier is too heavy for this app. Store attribution beside each cached file and show it in a "who made this?" panel, which handles [Wikimedia's credit requirement](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia) and the museums' credit requests in one feature.

## The Store's free signing collides with the scheduled task

Distribution is the one place where the minimal design costs money or features. Registration is [free](https://learn.microsoft.com/en-us/windows/apps/publish/partner-center/open-a-developer-account), and Store MSIX gets [free signing and no SmartScreen warnings worldwide](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options). But no official documentation covers registering scheduled tasks from packaged apps. The documented startup route is logon-only, and a [forum report](https://techcommunity.microsoft.com/t5/msix/msix-app-execution-alias-from-cannot-be-selected-from-task/m-p/3805369) describes an execution alias failing from Task Scheduler. A logon-only build would not refresh a PC that stays signed in for days, which is exactly the "daily" promise. One clue cuts the other way. Bing Wallpaper is itself MSIX, yet it has a daily task, which launches a helper from `%TEMP%`, and its manifest declares `unvirtualizedResources` commented as needed for that daemon ([package](https://download.microsoft.com/download/3c0e11a1-2e57-4bc3-b877-1a04248078a4/W011/0x00005001/BingWallpaper_1.1.459.0_x86.msix), [local check](../research_notes/Minimal%20Windows%20wallpaper%20app%20design/windows_mechanics.md)). So a packaged app can do this, at least with a restricted capability and a helper outside the package. Whether a third-party submission would pass is unknown.

So ship the **signed portable exe first**, through GitHub Releases and [WinGet, which accepts `portable` types](https://www.mintlify.com/microsoft/winget-cli/concepts/manifests), and add a Store build only if testing shows the task works there or logon-only proves acceptable. Do not ship unsigned as the main download: reputation [restarts every version](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation), and Smart App Control [blocks unsigned code](https://textslashplain.com/2026/04/28/smart-app-control/) that the cloud does not recognise. EV no longer buys instant trust, and reputation "can take several weeks and hundreds of clean installs" even when signed.

| Signing route | Cost | Catch |
|---|---|---|
| [Artifact Signing](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart) | [From $9.99/month](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation) | Individuals must be in the USA or Canada; a paid Azure subscription appears necessary |
| [SignPath Foundation](https://signpath.org/terms) | Free | OSS only, verifiable builds; publisher shows as SignPath Foundation |
| [OV certificate](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options) | $150-300/year | Hardware or HSM key storage; 460-day validity |

The right row depends on where you are based and whether the project is open source, neither of which the research established. A single-file design helps regardless, because Smart App Control checks every loaded module. Avoid UPX, which [can trigger antivirus heuristics](https://raw.githubusercontent.com/johnthagen/min-sized-rust/main/README.md), since [any flagged scan blocks a WinGet package](https://github.com/microsoft/winget-pkgs/blob/master/doc/Policies.md). Rust binaries have drawn [Defender false positives](https://github.com/rust-lang/rust/issues/88297), and so has [WinDynamicDesktop](https://github.com/t1m0thyj/WinDynamicDesktop/issues/274), though that evidence is anecdotal. For updates, read the version field from the manifest during the daily run, tell the user in settings, and let WinGet or the Store do the replacing. Self-replacement adds code and is likely to look suspicious to scanners.

## Eight untested behaviours gate the first release

Everything above is assembled from documentation and a partial prototype. These tests change system state, so none were run. Do them on a spare profile or VM. On this machine, pause Bing Wallpaper first, because its daily task will overwrite backreel's output.

| Test | If it fails or surprises |
|---|---|
| Full run cost: 4K decode, scale, encode, `SetWallpaper` | Replace the 3.8 MB figure; tune the pipeline before publishing numbers |
| Standard-user registration of the logon trigger ([reports conflict](https://qna.habr.com/q/1303758)) | Fall back from COM to `schtasks /create /xml`, then to an HKCU Run entry |
| `SetWallpaper` with several virtual desktops (undocumented; 292 desktop keys exist here) | Document the limitation; do not reach for internal APIs |
| `SetWallpaper` while Spotlight or slideshow is active (undocumented) | Adjust the first-run prompt and `BackgroundType` handling |
| Deleting a source file Windows still references | Lengthen retention; copy the current image on uninstall |
| `InteractiveToken` run in a switched-away session | Exit pending and rely on the logon trigger |
| Lock screen call from an unpackaged exe | Stays out of v1; package identity [needs a trusted signature](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps) anyway |
| Signed build under Smart App Control, plus an antivirus scan | Decides the signing route and when WinGet submission is viable |

## Conclusion

The defensible claim is narrower than "first multi-source wallpaper app", which would be false: John's Background Switcher, Wall/Art/Shift and Spice all exist. What was not found anywhere is the combination of an installer under about 10 MB, several unrelated sources, cross-source categories, per-monitor control and no ads. Nor does any surveyed app publish reproducible memory figures, even though many claim to be lightweight. A published, repeatable test may be worth more than the small binary itself. The "no resident process" claim needs checking first, since the process models of John's Background Switcher, DMT and Dynamic Theme were not verified. The opening is timely, given Bing's [full-desktop film ad](https://www.theregister.com/os-platforms/2026/09/08/bing-wallpaper-app-opens-harry-potters-chamber-of-ads/5295118) in September and its [desktop-click behaviour](https://www.windowslatest.com/2026/10/19/microsoft-promised-fewer-windows-11-ads-but-its-wallpaper-app-acts-like-adware-opening-bing-when-you-click-your-desktop/) in October, but the real competitor is Spotlight, which has been [the free default](https://learn.microsoft.com/en-us/windows/configuration/windows-spotlight/) since late 2024.

The decision that most needs your judgement is aesthetic, not technical. Without Bing, the default feed is museum art and Commons photography rather than glossy landscapes, and that may not be the product you pictured. Review around 50 images per category and source before writing the adapters, and get the Bing legal answer early, because those two results decide what the app feels like. Code is the cheap part: the core path has already been shown at about 225 KB.
